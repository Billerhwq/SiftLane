# Siftlane v0.3.0

## Highlights

- Added local user accounts, expiring bearer sessions, logout and login throttling.
- Added `admin`, `editor`, and `viewer` roles with flow ownership and private/team visibility.
- Enforced resource authorization across flows, runs, results, events, SSE, schedules and cancellation.
- Added append-only audit events and an administrator security-operations view.
- Moved third-party connector discovery into bounded child processes with a restricted environment.
- Ran all P1/P2 browser workflows under team authentication and added P3 team/audit acceptance.

## Upgrade

Existing flows, runs and schedules are assigned to the built-in local operator and remain team-visible. To enable team mode, set `SIFTLANE_ENGINE_AUTH_MODE=team` and provide `SIFTLANE_ENGINE_BOOTSTRAP_ADMIN_PASSWORD` for the first start. The password is only used when no team account exists.

Back up the SQLite data directory before first start. See `documentation/migrations.md` for validation and rollback limits.

## Known Limits

- This release provides users inside one deployment; it does not claim SaaS tenant isolation or enterprise SSO.
- Connector process isolation contains crashes, timeouts, oversized output and inherited secrets. It is not an OS sandbox for hostile packages.
- Repository branch protection still requires administrator verification before the P3 release governance gate can be closed.
