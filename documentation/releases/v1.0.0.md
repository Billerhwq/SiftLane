# Siftlane v1.0.0

## GA Scope

- Carries forward P1/P2 visual workflows, durable execution, bounded branch/loop/retry behavior, recovery, scheduling and reproducible release artifacts.
- Adds P3 team authentication, roles, owner/private boundaries, append-only audit and connector discovery isolation.
- Adds P4 managed connector lifecycle, the JSON Feed reference connector, encrypted scoped secrets and reliable NDJSON/Webhook delivery with dead letters and replay.
- Adds P5 schema readiness, liveness/readiness/Prometheus surfaces, structured logs, verified backup/restore, capacity and soak qualification, hardened Linux Compose inputs, accessibility checks and operational runbooks.

## Required Upgrade Action

1. Read `documentation/compatibility.md`, `migrations.md` and `upgrade.md`.
2. Create and verify an online backup before first start.
3. Preserve a stable `SIFTLANE_ENGINE_SECRET_KEY` of at least 32 characters; encrypted P4 credentials cannot be recovered without it.
4. For team mode, configure the bootstrap administrator password only for the first account creation, then remove it from the environment.
5. Require schema version 5 and `/health/ready=200` before enabling schedules or delivery targets.

## Qualified Boundary

The local GA qualification profile is a single Windows node with SQLite: 120 successful runs, 20 items each, concurrency 8, database below 64 MiB and completion within 75 seconds; a 30-second steady workload must retain all items within the published heap limits. Linux deployment is accepted only through the separate Ubuntu Compose CI job. These figures are a repeatable qualification floor, not a multi-node or hosted SLA.

## Compatibility

The stable public surfaces are `/api/v1`, compatible P2+ flow definitions, Connector SDK `siftlane.connector/v1`, schema versions 2-5 for forward upgrade, and backup manifest `siftlane.backup/v1`. In-place database downgrade is unsupported.

## Known Limits

- One engine node and SQLite; no automatic failover or cross-region recovery.
- Connector child processes provide bounded fault/environment isolation, not a hostile-code kernel sandbox.
- Webhook receivers must honor `Idempotency-Key` for end-to-end duplicate suppression.
- Browser automation, SaaS tenant isolation and enterprise identity providers are outside GA scope.
- Formal GA remains blocked until required GitHub branch-protection, exact-commit CI, Linux deployment and reviewer evidence are recorded.

## Rollback

Disable or roll back a faulty connector and pause a faulty target before considering engine rollback. For an engine or migration failure, stop writers, preserve the failed database/logs, restore the verified pre-upgrade backup with the prior matching artifacts and validate readiness/counts. Never run an older engine against a database that has accepted later writes and never move or replace a published tag's assets.
