# SiftLane 任务调度中心 PRD

## 1. Summary

任务调度中心把现有的侧边抽屉升级为 SiftLane 一级模块。用户可以在 World Monitor 式态势总览中查看计划健康度、未来触发、实时运行和失败信号，并在计划管理、执行记录、异常中心三个独立数据界面中完成高密度操作。总览左右信息 Dock 可独立收缩，把空间优先让给中央态势场。

首个版本复用现有 Cron、时区、数据库租约、幂等触发和权限接口，不在界面中展示后端尚未支持的调度策略。

## 3. Background

SiftLane 已经具备调度引擎和计划 CRUD，但前端只提供一个右侧抽屉。随着流程、计划和运行数量增加，用户无法快速回答以下问题：

- 当前有多少计划启用、暂停或失败？
- 接下来一段时间会触发哪些任务？
- 哪些流程正在运行、排队或需要处理？
- 某个计划最近一次发生了什么，应该从哪里进入运行详情？

因此需要把调度从辅助设置升级为持续运营入口。World Monitor 的多区域态势界面适合表达“全局状态 + 主操作场 + 实时活动”，Ant Design 适合承载高频管理表格、筛选、表单和状态反馈。

## 4. Objective

### 目标

让操作人员在 30 秒内了解调度系统是否健康，并在不离开当前模块的情况下完成计划管理或进入对应运行记录。

### Key Results

- 100% 的现有计划管理能力从一级页面可达。
- 创建、编辑、启停、立即运行和删除均有明确成功或失败反馈。
- 用户可在一个视口看到启用数、暂停数、错误数、运行中和排队状态。
- 左右信息 Dock 可独立收缩且保留数量摘要，收缩状态在刷新后保持。
- 计划、运行和异常的大数据列表使用独立全宽界面，不在总览中无限堆叠。
- 拖动、筛选、打开表单等高频交互不引起页面结构跳动或内容闪烁。
- 桌面 1440x900 和 1280px 宽度下的核心操作可完成。
- 浏览器测试覆盖计划创建、启停、触发、持久化和静态节点拖拽回归。

## 5. Market Segments

### 数据工程师

需要把多个采集流程按固定周期运行，并快速进入失败任务定位原因。

### 研究人员

需要确认采集计划何时再次运行，并在必要时立即触发一次采集。

### 小型数据团队负责人

需要从全局了解任务健康度、运行压力和计划归属，同时遵守现有角色权限。

### 约束

- 首版使用现有 SQLite 单机/受控服务器部署方式。
- 调度列表当前由已有接口完整返回，尚无服务端分页和高级筛选。
- 后端尚未定义错过执行、补跑、并发上限和时间窗口策略。

## 6. Value Propositions

| 用户任务 | 当前问题 | 新价值 |
| --- | --- | --- |
| 判断系统是否健康 | 需要分别查看计划和运行 | 一个视口聚合计划、队列和运行状态 |
| 找到下一次触发 | 抽屉逐条读取 | 24 小时运行带按时间排序展示 |
| 处理失败计划 | 只显示最后错误 | 错误计划集中筛选，并可进入对应运行 |
| 管理大量计划 | 抽屉空间不足 | 独立表格、搜索、状态筛选和批量扫描 |
| 立即执行 | 操作后上下文变化不明确 | 触发后自动进入对应运行记录并保留反馈 |

## 7. Solution

### 7.1 UX and User Flow

```text
左侧一级导航进入调度中心
        ↓
查看系统状态条与 24 小时运行带
        ↓
在左侧计划图层选择计划，在右侧任务情报查看上下文
        ↓
通过顶部视图进入计划管理 / 执行记录 / 异常中心
        ↓
创建或编辑计划 ──→ 保存后刷新总览与列表
        ↓
启停 / 立即运行 / 删除
        ↓
立即运行成功后进入运行记录并选中对应运行
```

桌面总览采用 World Monitor 的信息大屏拓扑：左侧“计划图层” Dock、中央 24 小时态势场、底部“计划风险 / 执行脉冲”实时信号面板、右侧“任务情报” Dock。左右 Dock 可独立收缩为 44px 摘要轨；1280px 初次进入时右侧默认收缩。计划表、运行表和异常列表不进入总览，分别由顶部视图切换进入独立全宽界面。本轮只设计桌面 Web，不设计移动端结构。

### 7.2 Key Features

#### 一级导航

- “任务调度”与流程编排、运行记录、采集结果并列。
- 当前模块具有明确选中状态和页面标题。

#### 态势总览

- 展示计划总数、启用、暂停、错误、运行中和排队数量。
- 24 小时运行带基于真实 `next_run_at` 排列任务，不生成虚假预测。
- 左侧计划图层只展示最多 6 个即将触发项，并可进入完整计划管理。
- 底部风险和执行信号只展示当前最相关的有限条目，并分别进入异常中心或执行记录。
- 右侧任务情报展示选中计划及其关联运行，支持进入运行详情。
- 左右 Dock 的展开/收起按钮提供可访问名称，状态写入本地存储。

#### 独立数据界面

- 顶部提供“调度态势、计划管理、执行记录、异常中心”四个稳定视图入口。
- 计划管理使用全宽 Ant Design 表格、计划/流程搜索和状态筛选。
- 执行记录使用独立全宽表格，支持按流程、运行 ID、活动和状态筛选。
- 异常中心在异常计划与失败运行之间切换，避免总览被长列表占满。

#### 计划管理

- 搜索计划名称和流程名称。
- 按全部、运行中计划、已暂停和错误筛选。
- 使用 Ant Design 表格展示状态、流程、Cron、时区、下次运行、最近运行和操作。
- 使用 Ant Design Drawer + Form 创建和编辑计划。
- 参数 JSON 在提交前校验并显示可操作错误。

#### 权限与状态

- Viewer 只读。
- Admin 可管理所有可见计划。
- Editor 遵循现有 owner/creator/visibility 规则。
- 空状态、加载、接口错误、无筛选结果和禁用状态均有明确界面。

### 7.3 Technology

- React、TypeScript、TanStack Query 继续作为状态与数据层。
- Ant Design 提供管理控件、表格、表单、Drawer、Tag、Progress 和反馈。
- React Flow 继续负责流程画布，不替换其核心交互。
- 后端继续使用 `/api/v1/schedules` 和 `/api/v1/runs` 等现有接口。
- 视觉系统采用明亮、连续、低圆角的操作台；World Monitor 只提供信息拓扑参考。

### 7.4 Assumptions

- 本轮数据规模可以由前端完成搜索和筛选。
- `next_run_at` 是后端计算后的唯一可信下一次触发时间。
- 运行记录中的 `flow_id` 足以完成首版计划到运行的导航联动。
- 高级调度策略需要先扩展后端模型，不能仅由前端添加控件。

### Acceptance Criteria

- 左侧一级菜单存在“任务调度”，点击后替换中心工作区。
- 计划 CRUD、启停、立即运行和删除与后端闭环通过。
- 总览与运行带只使用真实接口数据。
- 创建/编辑表单支持 Cron、时区、流程和 JSON 参数校验。
- 1440x900 和 1280px 宽度下无重叠、横向不可控溢出或文字截断。
- 左右 Dock 可独立展开和收缩；收缩后中央态势场自动获得空间，完整内容仍可恢复。
- 计划管理、执行记录和异常中心均为独立全宽视图，总览列表有明确数量上限和“查看全部”入口。
- 原流程拖拽无闪烁回归继续通过。
